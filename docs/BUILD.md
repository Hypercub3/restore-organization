# Build

The portable creator is a .NET Framework 4.8 Windows Forms application. Its generated scripts embed the shared C# engine and restore UI, compile them in stock Windows PowerShell 5.1, and contain compressed snapshot data.

## Portable creator

From PowerShell at the project root:

    .\build.ps1 -SkipShell

This uses the C# compiler provided with Windows .NET Framework. It writes the executable, configuration, and context-menu helper into dist. The helper is optional; it needs the full shell package to enable the menu.

The runtime source is generated by combining Core.cs and RestoreUI.cs. Keep their C# language features compatible with the Windows .NET Framework compiler and Windows PowerShell Add-Type. No external runtime packages are used.

## Full optional shell build

The current build uses these workspace-local tools:

- llvm-mingw 20261006 UCRT x86_64 from mstorsjo/llvm-mingw releases. SHA-256: 317492c456aa27ee607a5919f1d2d38dcdc1112516a24d0bf4b00d078f52d17a. Extract under .tools/llvm-mingw-20261006-ucrt-x86_64.
- Microsoft.Windows.SDK.BuildTools 10.0.28000.2705 from NuGet, extracted under .tools/sdk.
- OpenSSL from C:/Program Files/Git/usr/bin/openssl.exe.

Run:

    .\build.ps1

The build produces native x86, x64, and ARM64 shell DLLs and corresponding signed MSIX packages under dist/architectures. Each DLL links its compiler runtime statically. CertificateTrust.exe embeds the exact exported public certificate and performs only install/remove operations in LocalMachine TrustedPeople through UAC; it never accepts caller-selected certificate paths. Package registration stays in the original unelevated user process. MakeAppx packs complete architecture-specific packages containing the COM DLL, executable, configuration and assets; SignTool signs it with a project-local certificate. Windows signing uses the Windows cryptographic provider and can require execution outside a restricted build sandbox.

The signing key, PEM, and PFX stay in .tools, which is ignored by Git. **Do not distribute these private files.** The dist folder contains only the public .cer and signed package. The PFX password in the build script protects a local development container; it is not a production secret boundary. For wider distribution use a suitable production code-signing certificate.

MakeAppx validates each complete package without /nv. No external-location registration is used; this avoids sparse-package compatibility failures on Windows 10. The packaged COM component launches the stable portable copy using the current user's HKCU/Software/RestoreOrganization/ContextMenu/Location value. This copy includes the complete installer bundle for enable/disable and repair.

Changing package identity, publisher, or application ID requires keeping AppxManifest.xml and ContextMenu.ps1 consistent. The portable launcher deliberately omits package identity metadata: the COM shell extension receives identity from its optional package, while the creator can launch without registration.

## Tests

    .\test.ps1

Tests create unique fixtures only under tests/work. They verify content hashes, arrangements, conflicts, identity changes, independent script previews, true process interruptions, recovery, and hundreds of files. Offscreen Windows Forms renders are saved under build for visual inspection. The test executable is a build artifact and is not included in the user ZIP.

The optional native COM test requires w64devkit. The portable engine suite does not.

## Package

    .\package.ps1

This packages only the explicit user-facing file list and assets, never test fixtures or private keys. It saves a ZIP and SHA-256 checksum in the project root.

Installer validation: run tests/InstallerTests.ps1 in Windows PowerShell 5.1. Read-only validation is available through dist/ContextMenu.ps1 -Action Validate. Live installation is tested separately because it requires Windows administrator approval.

Registered COM activation can be tested with tests/RegisteredShellTests.cpp after enabling the feature for the same Windows account. Use the native x64 cross compiler with ole32, uuid, shell32 and advapi32 libraries. This test is separate from the default suite because it requires a live package registration.

The creator includes src/FolderPicker.cs, which uses the Windows IFileDialog COM interface in folder-selection mode. This source is intentionally excluded from the standalone restore payload because restore windows do not choose collection folders. Compile tests/FolderPickerTests.cs together with src/FolderPicker.cs as an STA .NET Framework executable referencing System.Windows.Forms.dll to exercise real native selection and cancellation.
